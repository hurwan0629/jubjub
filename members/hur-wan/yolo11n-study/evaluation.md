# 평가지표와 확인할 것

## 1. 모델 크기 · 속도 (01, 02 노트북)

| 지표 | 뜻 | 왜 보나 |
|---|---|---|
| 파라미터 수 | 모델이 학습한 숫자(가중치)의 개수 | 클수록 보통 정확하지만 무겁다 |
| 파일 용량 (MB) | `.pt` 파일 크기 | Jetson에 올릴 수 있는지 |
| GFLOPs | 이미지 1장 처리에 필요한 계산량 | 속도를 대략 예상 |
| 추론 시간 (ms) | 전처리 + 추론 + 후처리 시간 | 로봇이 실시간으로 반응할 수 있는지 |
| FPS | 1초에 처리하는 이미지 수 (= 1000 / 1장당 ms) | 카메라 영상을 따라갈 수 있는지 |

> PC(GPU)에서 잰 속도와 Jetson에서 잰 속도는 많이 다릅니다. 둘 다 따로 기록합니다.

## 2. 탐지 성능 (03 노트북)

먼저 용어 4개:
- **TP** (True Positive): 쓰레기를 쓰레기라고 맞게 찾음
- **FP** (False Positive): 쓰레기가 아닌데 쓰레기라고 함 (오탐)
- **FN** (False Negative): 쓰레기가 있는데 못 찾음 (미탐)
- **IoU**: 예측 박스와 정답 박스가 겹치는 비율 (0~1). 보통 0.5 이상이면 "맞췄다"고 봄

| 지표 | 계산 | 쉽게 말하면 |
|---|---|---|
| Precision (정밀도) | TP / (TP + FP) | "찾았다고 한 것 중에 진짜가 몇 %?" |
| Recall (재현율) | TP / (TP + FN) | "진짜 쓰레기 중에 몇 %를 찾았나?" |
| mAP@50 | IoU 0.5 기준, 클래스별 AP 평균 | 탐지 성능 대표 점수 (높을수록 좋음) |
| mAP@50-95 | IoU 0.5~0.95 여러 기준의 평균 | 박스를 얼마나 **정확한 위치에** 그렸는지까지 봄 |
| 클래스별 AP | 클래스마다 따로 계산 | 캔은 잘 찾고 종이는 못 찾는 식의 차이 확인 |
| Confusion matrix | 정답 클래스 vs 예측 클래스 표 | 무엇을 무엇으로 헷갈리는지 |

**우리 로봇에서 중요한 것:** FP(오탐)는 로봇이 엉뚱한 데로 가게 만들고, FN(미탐)은 쓰레기를 놓치게 만듭니다.
처음에는 **Precision을 더 중요하게** 보고, 확실하지 않으면 접근하지 않는 쪽으로 갑니다 (`unknown` 처리).

## 3. 확인할 것 (체크리스트)

### 사전학습 모델 그대로 (01~02)
- [ ] YOLO11n이 원래 아는 80개 클래스(COCO) 중 쓰레기와 관련 있는 것: `bottle`, `cup`, ...
- [ ] 캔, 비닐, 종이처럼 **원래 클래스에 없는 쓰레기**는 어떻게 나오는지 (못 찾나? 다른 이름으로 찾나?)
- [ ] confidence 기준(`conf`)을 0.1 / 0.25 / 0.5로 바꾸면 탐지 개수가 어떻게 변하는지

### 사진 조건 바꿔 보기 (02~03)
- [ ] 가까이 vs 멀리 (작은 물체)
- [ ] 밝은 곳 vs 어두운 곳, 그림자
- [ ] 배경: 바닥, 잔디, 흙, 낙엽
- [ ] 일부가 가려졌을 때, 찌그러졌을 때
- [ ] 쓰레기가 아닌 것(돌, 낙엽, 신발)을 쓰레기로 착각하는지

### 기억해 둘 것
- [ ] bbox는 **사진 속 픽셀 좌표**일 뿐, 로봇에서 실제 거리(cm)가 아님
- [ ] 공개 데이터셋 점수가 높아도 **우리 카메라 · 우리 장소**에서는 다를 수 있음
