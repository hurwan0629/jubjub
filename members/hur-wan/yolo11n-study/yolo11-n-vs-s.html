YOLO11n과 YOLO11s 비교

두 모델은 층 구조가 완전히 같고, 층마다 채널 수만 s가 n의 2배입니다. 이 페이지의 숫자는 2026-11-07에 이 노트북에서 직접 잰 값이고, COCO 정확도만 Ultralytics 공식 문서 값입니다.

파라미터가 4배가 아니라 3.6배인 이유

Conv 가중치 개수는 입력 채널 수 × 출력 채널 수 × 커널 크기에 비례합니다. 그래서 채널이 2배가 되면 가중치는 대략 4배가 됩니다. 예를 들어 1번 Conv는 n이 4,672개, s가 18,560개로 4.0배입니다.

예외가 두 군데 있습니다. 0번 층은 입력이 RGB 3채널로 고정이라 2배만 늘어납니다. 23번 Detect 헤드는 클래스 수(80)와 박스 표현(64)에 맞춘 고정 채널이 있어서 464,912개에서 850,368개로 1.8배만 늘어납니다. 이 둘 때문에 전체로는 3.6배가 됩니다.

GPU에서 n과 s 속도가 같게 나온 이유

이 노트북 GPU는 YOLO11s의 21.8 GFLOPs도 금방 계산합니다. 그래서 측정 시간의 대부분이 계산이 아니라 파이썬 코드 실행과 GPU에 작업을 넘기는 고정 비용입니다. CPU에서는 계산량이 시간에 그대로 드러나서 s가 1.8배 느립니다. Jetson처럼 연산 능력이 작은 장치에서는 GFLOPs 차이가 시간 차이로 나타날 가능성이 크니, 장비가 오면 직접 재 봐야 합니다.

같은 GPU에서 float16(half=True)으로 바꿔도 n은 13.9ms에서 13.6ms, s는 12.8ms에서 13.3ms로 차이가 없었습니다. 이유는 위와 같습니다. 그리고 ultralytics 8.4에서는 half를 쓰면 앞으로 없어질 인자이니 quantize를 쓰라는 경고가 나옵니다.

구조

블록 설명

Conv
3×3 합성곱, BatchNorm, SiLU 활성화를 묶은 것. 보폭(stride) 2면 가로세로가 절반이 됩니다. 백본의 0, 1, 3, 5, 7번이 모두 보폭 2라서 640이 다섯 번 절반이 되어 20이 됩니다.
C3k2
입력을 두 갈래로 나눠 한쪽만 작은 합성곱 여러 개를 거친 뒤 다시 합치는 블록. 해상도는 그대로 두고 특징을 다듬습니다.
SPPF
5×5 맥스풀링을 세 번 연달아 적용하고 결과를 모두 이어 붙입니다. 한 칸이 더 넓은 주변을 보게 됩니다.
C2PSA
어텐션 블록. 특징맵에서 중요한 위치에 더 큰 가중치를 줍니다. YOLO11에서 새로 들어간 부분입니다.
Upsample
가로세로를 2배로 키웁니다. 가장 가까운 값을 복사하는 방식이라 파라미터가 0개입니다.
Concat
두 특징맵을 채널 방향으로 이어 붙입니다. 해상도가 같아야 합니다. 파라미터 0개.
Detect
세 해상도의 칸마다 박스 위치와 80개 클래스 점수를 냅니다. 박스는 16단계 분포로 예측한 뒤 좌표 4개로 바꿉니다 (DFL, 그래서 내부 채널이 4×16=64).

s의 출력 크기는 채널만 2배이고 해상도는 n과 같습니다. 출력 크기는 1×3×640×640 입력을 실제로 넣어서 각 층에서 잰 값입니다.

입력 이미지 해상도

기본 입력 크기는 imgsz=640입니다. 모델은 사진을 그대로 받지 않고, 긴 변을 640에 맞춰 비율을 유지한 채 줄입니다. 이 과정을 letterbox라고 부릅니다.

  • 입력 텐서 모양은 (1, 3, H, W)입니다. 1은 사진 장수, 3은 RGB 채널이고, 값은 0~255를 255로 나눈 0~1 사이 float32입니다.
  • H와 W는 32의 배수여야 합니다. 보폭 2인 Conv가 다섯 번 있어서 2를 다섯 번 곱하면 32이기 때문입니다. 640 ÷ 32 = 20이 가장 작은 특징맵 크기입니다.
  • predict()는 기본으로 정사각형을 고집하지 않아서 bus.jpg는 480×640으로 들어갑니다. 이때 출력 칸 수는 8400이 아니라 60×80 + 30×40 + 15×20 = 6300입니다.
  • imgsz를 줄이면(예: 320) 칸 수와 계산량이 약 4분의 1로 줄어 빨라지지만, 작은 물체를 놓치기 쉬워집니다.

결과 형태

모델이 바로 내는 값 (NMS 전)

640×640 입력이면 모양이 (1, 84, 8400)입니다. 8400은 세 해상도의 칸을 모두 합친 수(6,400 + 1,600 + 400)이고, 칸 하나가 물체 후보 하나입니다. 84는 칸마다 나오는 값의 개수입니다.

위치값뜻
0~3cx, cy, w, h박스 중심 좌표와 너비, 높이 (입력 이미지 픽셀 단위)
4~83클래스 점수 80개각 클래스일 확률 (0~1). 가장 큰 값이 그 칸의 클래스와 confidence가 됨

YOLO11은 "물체가 있을 확률"을 따로 내지 않습니다. 클래스 점수 중 가장 큰 값을 그대로 confidence로 씁니다.

사용자가 받는 값 (NMS 후)

8400개 후보 중 confidence가 conf(기본 0.25)보다 낮은 것을 버리고, 같은 물체에 겹쳐 있는 박스는 NMS로 하나만 남깁니다. 남은 N개가 Results.boxes에 들어갑니다. 좌표는 원본 사진 기준 픽셀로 되돌려져 있습니다.

속성모양내용
boxes.xyxy(N, 4)왼쪽 위 x, y와 오른쪽 아래 x, y (원본 픽셀)
boxes.xywhn(N, 4)중심 x, y와 너비, 높이를 0~1로 나눈 값
boxes.conf(N,)confidence
boxes.cls(N,)클래스 번호. model.names[번호]로 이름 확인
boxes.data(N, 6)위 값을 한 줄로 합친 것. x1, y1, x2, y2, conf, cls

우리 프로젝트에서 볼 점

  • COCO 정확도는 s가 7.5점 높고(39.5와 47.0), 대신 파라미터는 3.6배, 계산량은 3.3배입니다.
  • Jetson에서 돌릴 거라면 n으로 시작해서 실제 FPS를 재고, 정확도가 모자랄 때 s를 비교하는 순서가 안전합니다.
  • 노트북 GPU에서 잰 속도는 Jetson 속도를 알려 주지 않습니다. CPU 결과(30ms와 54ms)가 차이를 더 잘 보여 줍니다.
  • 쓰레기 클래스로 다시 학습하면 클래스 수가 80에서 4개 정도로 줄어서 출력이 (1, 8, 8400)이 되고, Detect 층 파라미터도 줄어듭니다.

측정 조건

ultralytics 8.4.143, torch 2.14.0 (CUDA 13.0), Python 3.12, Windows 11, RTX 5070 Ti Laptop GPU. 파라미터 수와 층별 출력 크기는 torch.zeros(1, 3, 640, 640)을 넣어 측정했습니다. 연산량은 ultralytics의 get_flops 값입니다. COCO mAP는 Ultralytics YOLO11 공식 문서 표의 값이고 직접 재지 않았습니다.
