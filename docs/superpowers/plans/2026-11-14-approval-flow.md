# 공원 승인 및 순찰 설정 연결

**Goal:** Figma Page 2의 가입 → 공원 선택 → 승인 요청 → 승인 후 5단계 순찰 설정을 실제 API와 연결한다.
**Architecture:** Expo/TypeScript와 기존 FastAPI 계약을 유지한다. 승인 전 토큰은 검색·신청에만 사용하고 홈 진입은 승인 상태로 분기한다. 서버 권한 검사는 유지한다.
**Scope:** 네이버 지도 인증 설정, 총관리자 포털 및 로봇 실시간 API 구현은 제외한다. 웹 도식 지도를 그대로 사용한다.

## 결정
- 가입 정보의 다음 버튼은 계정을 생성하고 내부 로그인 후 공원 선택으로 이동한다. 비밀번호는 navigation params나 저장소에 남기지 않는다.
- 기존 계정은 재로그인으로 미완료 신청을 이어간다. 승인 대기는 상태 재확인 및 로그아웃을 제공한다. 반려는 사유와 재신청을 제공한다.
- 승인 완료 안내 확인 후 최초 설정으로 이동한다. 승인된 공원 변경은 기존 서버 정책에 맞춰 담당자 문의로 안내한다.
- 초기 설정 및 편집은 PUT /route 성공 후에만 완료를 표시한다. 실패는 화면에 표시하고 입력을 유지한다.

## 작업
- [x] API 회귀 테스트: 승인 상태별 이동, 공원 선택 요청, 실제 경로 저장, 저장 실패, 목업 상태 유지.
- [x] 타입·API·훅: 로그인 role/parkStatus/routeSetupDone, GET/PUT /park, 실제 /route 활성화, 완료 저장.
- [x] 가입·로그인 화면: 공원 선택과 승인 대기/완료/반려 안내, 승인 전 홈 차단.
- [x] 순찰 초기 설정: 승인된 공원 로드, 5단계로 정리, 서버 저장 및 오류 처리.
- [x] 편집·설정 화면: 로딩/오류/저장 실패 안내, 승인된 공원 변경 차단.
- [x] 검증: Node 회귀 테스트, npm run check, 웹 번들 생성, 독립 코드 리뷰.

## 검증 초점
승인 전·반려·이미 설정 완료 계정, API 401/503, 저장 실패 후 재시도, 재로그인 시 최초 설정 반복 방지, 승인된 공원 변경 시 기존 데이터 보존.

## 진행 기록
- 기존 wooki 작업 폴더에서 작업한다. 사용자 요청의 실행 위치를 유지하며 root package-lock.json은 보존한다.
- baseline: npm.cmd run typecheck 통과. PowerShell 실행 정책 때문에 npm.cmd를 사용한다.
- 최종 검증: npm.cmd test 8/8, npm.cmd run check exit 0, git diff --check 통과. 기존 PointList/ReportScreen 경고 4개 유지.
- 독립 리뷰의 가입 취소 후 늦은 인증 응답 및 목업 계정 덮어쓰기 문제는 추가 회귀 테스트 RED→GREEN으로 수정.
- 웹 export는 dist에 index.html 및 번들 생성 완료(Exported: dist). 출력 후 CLI가 종료되지 않아 작업 프로세스만 종료했다.
- 브라우저 확인은 CUA가 현재 URL을 확인하지 못해 중단. 실제 DB 계정 생성·관리자 승인·실제 브라우저 전체 흐름 검증은 수행하지 않았다.
- 정책 결정: 서버의 승인 전 인증은 검색·신청을 위해 유지하고 앱 진입만 제한한다. 승인된 공원 변경은 서버 정책대로 담당자 문의로 안내한다.
- 총관리자 포털 및 홈 로봇/알림/보고 실제 API 연결은 이 변경 범위 밖이며 README에 명시했다.
