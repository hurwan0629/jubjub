# Robot Protocol API Implementation Plan

**Goal:** DB 0015와 로봇 통신 문서에 맞춰 기존 API와 로봇 메시지 수신·순찰 제어를 연결해요.
**Architecture:** 기존 FastAPI/SQLAlchemy 구조에서 조회·권한·기록은 services, 입력 검증은 schemas에 둬요. 로봇 연결과 명령 응답은 단일 프로세스 메모리 레지스트리가 관리해요. 명령 전 기록을 커밋하고 로봇의 수락·종료를 구분해요.
**Tech Stack:** FastAPI, Pydantic 2, SQLAlchemy 2, asyncio, React/TypeScript.
**Spec:** Confluence 현재 DB 7471105 v27, 로봇-서버 AYC9 v14.

## Constraints
- 기존 camelCase 응답과 에러 형식을 유지해요. 로봇 WebSocket 메시지는 문서의 snake_case를 사용해요.
- 원문 토큰은 등록·재발급 응답에서만 제공하고 DB에는 SHA-256만 저장해요.
- 로봇 신원은 헤더로 인증해요. 공원·로봇·순찰 소유권과 메시지 재전송을 검증해요.
- 과거 기록의 발생 시각과 현재 상태 갱신 시각을 구분해요. offline은 서버만 설정해요.
- 탐지 사진은 검증한 JPEG만 UUID 기반 R2 key로 저장해요.
- 배터리 비율과 낮은 전압 기준은 문서에 확정값이 없어 임의로 계산하지 않아요.
- 기존 wooki 작업 흐름을 유지해요. 실제 로봇 명령 및 공용 DB 테스트 데이터 쓰기는 하지 않아요.

## Tasks
- [x] returning·방향·토큰 응답 회귀 테스트의 실패를 확인한 뒤 서버/앱/웹 타입과 표시를 맞췄어요.
- [x] 좌표 변환, 메시지 입력 검증, 권한별 기록 조회 및 토큰 재발급을 구현했어요.
- [x] hello/status, 지점·탐지·수거·종료·오류 수신을 원자적 기록과 중복 방지로 구현했어요.
- [x] WebSocket 연결 교체·단절·명령 ack와 수동/시간표 순찰 실행을 구현하고 통합 테스트했어요.
- [x] 웹의 토큰 표시 및 앱/웹 API 함수와 새 응답 계약을 맞췄어요.
- [x] 독립 리뷰의 재접속·과거 오류·연결 교체 문제를 회귀 테스트로 재현하고 수정했어요. 계약은 server/ROBOT_PROTOCOL_API.md에 정리했어요.

## 검증 참고

로봇 API 통합 테스트 16건, 앱 API 테스트 23건, 웹 테스트 12건을 확인했어요. 공용 DB alembic check도 추가 변경 없음이에요.
최종 서버 전체 검사는 226 passed, 12 skipped이고 Ruff 검사와 소스 99개 파일 포맷 검사도 통과했어요. 웹 타입·포맷 검사와 프로덕션 빌드도 통과했어요.
앱의 저장소 파일 101개와 새 파일을 포함한 별도 타입 검사는 통과했어요. 원래 전체 타입 검사는 Git에서 제외된 로컬 screens/logs의 기존 누락 타입·훅 때문에 실패하며, 해당 사용자 파일은 수정하거나 삭제하지 않았어요. 기존 앱 린트 경고 4개도 이번 범위 밖이에요.

## Decisions
- 배터리는 전압만 응답해요. 비율은 배터리 사양 확정 뒤 추가해요.
- 자동 시간표 실행은 ROBOT_SCHEDULE_ENABLED 설정으로 켜요. 개발 기본값은 false예요.
- WebSocket은 단일 worker 실행을 지원해요. 다중 worker는 외부 연결 라우팅 구현 전 지원하지 않아요.
- 기존 공원 기준점이 없는 로봇은 상태의 SLAM 좌표는 저장하되 지도 좌표는 NULL로 둬요. 위경도가 필수인 탐지/오류는 기준점 설정이 없으면 저장을 거부해요.
