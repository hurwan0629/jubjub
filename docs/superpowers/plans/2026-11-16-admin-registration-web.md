# 총관리자 가입 승인 웹 구현 계획

후속 사용자 요청에 따라 화면 위치는 독립 web/ 프로젝트로 변경했다. 현재 구조와 검증은 [앱·웹·서버 분리 계획](2026-11-16-separate-admin-web.md)을 따른다.

**Goal:** Figma Page 4의 W-02를 기존 Expo 웹에 구현하고 실제 인증·가입·승인·반려·경로 저장 API 흐름을 검증한다.

**Sources:** Confluence JUBJUB 기획 v6 (8519760, 2026-11-16 KST), Figma 8jxiaGJ8smbceYuXug5roD Page 4 / 289:710, 289:1060, 289:1380, 294:786, 289:1680.

**Architecture:** 기존 로그인과 role 분기를 재사용한다. 총관리자 진입 화면을 W-02 레이아웃으로 교체한다. 조회와 변경은 전용 API/훅으로 처리하며 관리자 기능은 목업으로 성공을 가장하지 않는다. 앱의 색·글꼴·컴포넌트와 Figma 원본 아이콘을 사용한다.

## 범위와 결정
- 이번 요청은 관리자 가입 심사 화면이며 홈·보고서 전체 구현은 포함하지 않는다. 메뉴의 미구현 화면은 준비 중 안내를 명확하게 제공한다.
- v6가 우선: Figma에 없는 반려와 반려 사유 입력을 추가한다. 승인 취소는 로봇 회수와 함께 서버에서 원자적으로 처리하고 작업 중인 로봇이 있으면 거부한다.
- 신청 전체 목록을 페이지 단위로 읽고 필터별 숫자를 실제 데이터로 계산한다. 담당 로봇은 실제 등록 목록과 parkId로 연결한다.
- 승인 시 미할당 idle/offline 로봇을 선택할 수 있다. 서버 계약대로 로봇 없이도 승인 가능하다.
- 대기/반려/취소 상태에서 로그인·기존 토큰의 업무 접근을 차단한다. 기존 공원과 사용자의 운영 데이터는 임의로 변경하지 않는다.
- 검증은 격리 DB의 실제 ORM·HTTP API와 가능한 브라우저 UI를 사용한다. 공유 DB에 임의 계정을 남기지 않는다. UI 검증 제한이 있으면 구분해 보고한다.

## 진행 기록
- 기획안 v6와 Figma Page 4의 목록·필터·승인 후 화면 조회 완료.
- 구현은 현재 wooki 작업공간에서 진행: 실행 중인 로컬 앱·서버와 같은 checkout을 유지한다. 별도 배포는 하지 않는다.
- Ruling: 승인 취소 후 DB 상태는 rejected이며 입력한 취소 사유를 저장한다. 기존 상태 모델을 유지하면서 로그인·기존 토큰 접근을 차단한다. 경로·시간표는 삭제하지 않는다.
- 실제 앱 TS API 모듈 → 로컬 Uvicorn HTTP → 격리 SQLite ORM 연결로 가입/공원 검색/승인 전 차단/승인과 로봇 배정/경로·시간표 저장/재로그인/재조회/반려/승인 취소/기존 토큰 차단을 검증했다. 모의 fetch는 사용하지 않았다. 공유 Supabase 데이터는 변경하지 않았다.
- 최종 리뷰 1건: offset 10000 제한과 전체 목록 페이지 조회 계약 불일치 수정. 10100개 페이지 경계 프론트 테스트와 서버 offset10100 검증 통과.
- 검증: 앱 테스트 14개, 서버 전체 테스트 101개 통과. npm run check 통과(기존 경고 4개). Ruff check 통과, Ruff format --check app alembic tests 통과. 루트 단위 Ruff format은 기존 환경에서 내부 오류로 종료되어 실제 Python 소스 디렉터리를 명시해 검증했다.
- 웹 번들 생성 확인. Figma 원본 SVG 9개는 로컬 파일의 비어 있지 않음·루트 크기·호출부 크기를 대조했다. 브라우저 호스트가 unavailable이라 실제 화면 클릭·스크린샷 비교는 수행하지 못했다. 이 제한을 완료 보고에 명시한다.
