0결론 먼저

프론트엔드 = app/ 폴더 하나예요. Expo(React Native) + TypeScript로 만든 휴대폰 앱이고, 리뷰할 코드는 app/src/ 아래 약 77개 파일, 6,300줄이에요.

코드는 4층짜리 건물처럼 생겼어요. 위층은 아래층만 부르고, 거꾸로는 부르지 않아요.

화면 screens/→ 데이터 훅 hooks/→ 서버 통신 api/→ 목업 또는 실제 서버 api/mock/ · FastAPI

그리고 모든 층이 같이 쓰는 공통 재료가 옆에 있어요: theme/(색·글자 크기), components/(버튼·카드 같은 공통 부품), utils/(계산 함수).

✅ 추천 리뷰 순서 한 줄 요약 입구(App.tsx·navigation) → 재료(theme·Text) → 데이터 길(api/client → types → useApi) → 견본 화면(HomeScreen) → 기능별 화면(로그인 → 경로 처음 설정 → 지도 → 나머지 탭)
📌 지금 서버와 실제로 연결된 것은 3가지뿐 로그인·회원가입(auth), 내 정보(me), 공원 검색(parks). 나머지(로봇 상태, 지도, 알림, 경로 저장 등)는 전부 가짜 데이터(목업)로 화면만 돌아가요. → api/client.ts의 SERVER_READY 목록이 이걸 정해요.

1큰 그림: 폴더가 하는 일

건물로 비유하면, 손님(사용자)이 보는 1층 매장이 화면, 매장 뒤 창고 직원이 훅, 바깥 공장에 주문 넣는 사람이 api, 공장이 아직 없을 때 쓰는 샘플 상자가 목업이에요.

screens/
화면 11개 + 화면 전용 부품. 사용자가 보고 누르는 곳. 데이터는 직접 가져오지 않고 훅에게 받아요.
↓ 훅을 불러요
hooks/
데이터 훅 (useRobotStatus 등). "데이터 / 불러오는 중 / 오류"를 한 묶음으로 화면에 넘겨 줘요. 공통 뼈대는 useApi.ts.
↓ api 함수를 불러요
api/
서버 통신 함수. "자원"(robot, parks, auth…)마다 파일 하나. 각 함수 안에서 "목업이냐 서버냐"를 골라요.
↓ 둘 중 하나로
api/mock/ · 서버
목업(앱 안의 가짜 데이터) 또는 FastAPI 서버(server/ 폴더, 이번 리뷰 범위 밖).

📖 이 섹션 용어

Expo / React Native
자바스크립트로 안드로이드·iOS 앱을 같이 만드는 도구. Expo는 그걸 더 쉽게 해 주는 묶음이에요.
훅 (hook)
use로 시작하는 함수. 화면에 "기억할 값"이나 "불러온 데이터"를 붙여 줘요.
목업 (mock)
진짜 서버 대신 쓰는 가짜 데이터. 서버가 없어도 화면을 만들 수 있게 해요.
디자인 토큰
색·크기 같은 디자인 값에 이름을 붙인 것. #748bff 대신 colors.brand.

2어떤 순서로 파일을 볼까 (추천 리뷰 순서)

원칙: 아래층(재료) → 위층(화면). 재료를 먼저 알면 화면 코드를 읽을 때 "이건 어디서 온 거지?"가 사라져요. 단, 맨 처음엔 입구부터 봐서 전체 화면 지도를 머리에 넣어요.

입구: 앱이 켜지는 곳

index.tsApp.tsxsrc/navigation/index.tsx

index.ts가 App을 등록 → App.tsx가 글꼴(Inter, Noto Sans KR, Fredoka)을 다 불러온 뒤 RootNavigator를 띄워요. navigation/index.tsx에 모든 화면 목록과 화면 ID(C-01, A-04…)가 주석으로 있어요.

왜 먼저? 여기가 "건물 안내도"예요. 화면이 몇 개고 어디서 어디로 가는지 5분이면 파악돼요.

디자인 재료

theme/index.tstheme/colors.tstheme/typography.tstheme/spacing.tscomponents/Text.tsxcomponents/Icon.tsxicons.ts

모든 화면이 <Text variant="13-bold" color="textSub">처럼 씁니다. 13-bold = Figma의 "JUBJUB/13 · 굵게". 이 규칙을 알아야 화면 코드가 읽혀요.

데이터 길 (가장 중요)

api/client.tsapi/types.tsapi/mock/robot.tsapi/robot.tshooks/useApi.tshooks/useRobot.ts

로봇 상태 하나만 따라가 보면 다른 자원도 전부 같은 모양이에요.

// ① 화면: HomeScreen.tsx — 훅만 불러요
const { data: robot } = useRobotStatus();

// ② 훅: hooks/useRobot.ts — 5초마다 다시 불러요(폴링)
useApi(() => getRobotStatus(), [], { refreshMs: 5000 });

// ③ api: api/robot.ts — 목업이냐 서버냐 고르기
return mockFor('robot')
  ? mockResponse(mockRobot)        // 가짜 데이터를 0.2초 뒤에 돌려줌
  : request('/robot/status');    // 진짜 서버에 GET 요청

// ④ client.ts — mockFor의 판단 기준
//   주소(.env)가 비었거나, SERVER_READY 목록에 없으면 → 목업
const SERVER_READY = ['auth', 'me', 'parks'];

client.ts에는 이 밖에 에러 모양 통일(ApiError)과 로그인 토큰 붙이기(setAuthToken)가 있어요. 로그인 화면 리뷰 때 다시 나와요.

견본 화면: 홈

screens/HomeScreen.tsxcomponents/StatusBadge.tsxcomponents/AlertCard.tsxcomponents/StatRow.tsxcomponents/Card.tsx

파일 첫 줄에 "새 규칙으로 쓴 예시 화면"이라고 적혀 있어요. 훅 5개(로봇 상태, 작업 대기열, 오늘 요약, 알림, 판단 로그)를 쓰고 공통 부품으로 조립해요. 다른 화면이 이 견본을 잘 따랐는지 비교하는 기준이 돼요.

기능 ①: 로그인 · 회원가입 (서버 연결됨)

screens/SplashScreen.tsxscreens/auth/AuthLayout.tsxscreens/auth/LoginScreen.tsxscreens/auth/SignUpEmailScreen.tsxscreens/auth/PrivacyConsentDialog.tsxscreens/auth/privacyConsent.tsutils/validation.tsapi/auth.tscomponents/FormFields.tsx

시작화면(3초) → 로그인. 로그인 응답의 isFirstLogin이 true면 경로 처음 설정, 아니면 홈으로 가요. 회원가입은 입력 검사(validation.ts) → 서버 오류(409 중복, 422 형식)를 칸별로 보여 줘요.

기능 ②: 순찰 경로 처음 설정 (7단계 마법사)

screens/route-setup/RouteSetupScreen.tsxroute-setup/parts.tsxroute-setup/steps.tsxhooks/useParks.tsapi/parks.tsutils/route.ts

RouteSetupScreen이 "지금 몇 단계인지(step)"와 모은 값(공원, 분리수거장, 지점, 시간표)을 들고 있고, 각 단계 화면은 steps.tsx(629줄, 가장 큰 파일)에 있어요.

1 시작→2 공원 찾기서버 검색→3 분리수거장→4 지점 찍기→5 순서→6 시간표→7 완료

useParks.ts는 "글자를 칠 때마다 서버를 부르지 않게 0.3초 기다렸다 검색(디바운스)" + "20개씩 더 보기(페이지)"를 직접 구현해서 useApi를 안 써요. 다른 훅과 모양이 달라서 꼼꼼히 볼 곳이에요.

기능 ③: 지도 계열

components/parkMapTypes.tscomponents/ParkMap.tsxcomponents/ParkMap.web.tsxcomponents/ParkMapSchematic.tsxutils/geo.tsscreens/MapScreen.tsxscreens/route-edit/RouteEditScreen.tsx

타입 → 지도 부품 → 지도 화면 → 경로 편집 순서로 읽어요. ParkMap은 상황에 따라 그림이 2가지예요:

  • 개발용 빌드(네이티브): 진짜 네이버 지도 (NaverParkMap)
  • 웹 · Expo Go: 네이버 지도 모듈이 없어서 그림 지도 (ParkMapSchematic). 좌표 ↔ 그림 위치를 비율로 바꿔 같은 동작을 흉내 내요.

경로 편집 화면은 처음 설정의 부품(PointList, ScheduleList, AddTimeSheet, PointNameSheet)을 그대로 재사용해요. 그래서 ②를 먼저 보면 ③이 빨라요.

나머지 탭과 설정

screens/AlertsScreen.tsxscreens/ReportScreen.tsxscreens/SettingsScreen.tsxcomponents/TabBar.tsxapi/account.ts

알림(필터 칩 + 목록), 일일 보고(도넛 그래프), 설정(알림 켜기/끄기, 로그아웃, 공원 변경). 비교적 단순해서 마지막에 봐요.

📖 이 섹션 용어

폴링 (polling)
정해진 간격(여기선 5초)마다 "바뀐 거 있어?" 하고 다시 물어보는 방식.
디바운스 (debounce)
입력이 멈출 때까지 잠깐 기다렸다가 한 번만 실행. "ㅎ, 하, 한…" 칠 때마다 검색하지 않게 해요.
페이지네이션
결과를 한 번에 다 받지 않고 20개씩 나눠 받는 것 (limit, offset).
Expo Go
QR 코드로 바로 앱을 열어 보는 테스트용 앱. 네이버 지도 같은 네이티브 모듈은 못 넣어요.

6리뷰 때 짚어 볼 곳

코드를 읽으면서 눈에 띈 점이에요. "버그 확정"이 아니라 팀에 물어볼 질문 목록으로 쓰면 좋아요.

① 처음 설정에서 고른 경로가 저장되지 않아요 RouteSetupScreen은 공원·분리수거장·지점·시간표를 화면 상태(state)에만 들고 있다가 끝나요. saveRouteConfig() 같은 저장 호출이 없어서, 홈으로 가면 고른 값이 사라져요. (저장 API는 RouteEditScreen만 써요.)
② 서버 연결 시 매번 "처음 설정"으로 가요 api/auth.ts의 completeRouteSetup()은 목업일 때만 동작해요(주석에도 적혀 있음). 서버 쪽 완료 API가 생기기 전까지는 새 계정이 로그인할 때마다 C-03이 떠요.
③ 로그인 토큰이 메모리에만 있어요 client.ts의 authToken은 변수 하나라 앱을 끄면 사라져요. 401(로그인 만료) 응답을 받았을 때 로그인 화면으로 보내는 공통 처리도 아직 없어요.
④ 일일 보고 화면이 하드코딩 ReportScreen의 재질별 수량·시간대별 막대·할 일이 파일 안 상수이고, 날짜도 new Date(2026, 10, 6)로 고정이에요. useDailyReport 훅과 getDailyReport api는 이미 있으니 연결만 하면 돼요. 규칙("화면은 훅으로만 조회")과도 어긋나요.
⑤ 오류 처리가 빠진 곳
  • SettingsScreen의 handleToggle, handleLogout: await 실패 시 잡는 곳(try/catch)이 없어요
  • useApi: 오류가 나도 이전 data를 그대로 둬요. 의도라면 괜찮지만 화면이 "오래된 값인지" 표시하지 않아요
  • 홈·지도 등 대부분 화면이 loading/error를 화면에 보여 주지 않아요
⑥ 확인해 볼 작은 것들
  • MapScreen의 "히트맵" 칩: 고를 수는 있지만 지도 그림은 바뀌지 않아요 (아직 미구현)
  • 목업 함수가 모듈 변수를 직접 바꿔요 (mockTasks.push, mockRobot.state = 'idle'). 테스트 간 값이 섞일 수 있어요
  • 로그아웃의 navigation.getParent()?.getParent()?.reset(...): 화면 구조가 바뀌면 조용히 안 될 수 있어요
  • 안 쓰는 Txt.tsx, 화면 없는 api 함수들(sendRobot, ackNotification 등)은 남길지 정하기
  • steps.tsx가 629줄로 가장 커요. 단계별 파일로 나눌지 논의
✅ 잘 되어 있는 점 (리뷰 코멘트에 같이 남기면 좋아요)
  • 4층 구조와 mockFor('자원') 덕분에 서버가 API를 하나 만들 때마다 SERVER_READY에 한 단어만 추가하면 돼요
  • 늦게 온 응답 버리기(alive 플래그)가 useApi, useParkSearch에 일관되게 들어가 있어요
  • 네이버 지도 모듈이 없을 때 앱이 멈추지 않도록 미리 확인 후 그림 지도로 바꾸는 처리
  • 경로 설정과 경로 편집이 같은 부품을 공유해서 중복이 적어요

7전체 용어 사전

TypeScript
자바스크립트에 "이 값은 숫자, 이건 글자" 같은 타입을 붙인 언어. 실수를 미리 잡아 줘요.
컴포넌트
화면을 이루는 레고 조각. 함수 하나가 화면 조각 하나를 그려요.
state (상태)
화면이 기억하는 값. 바뀌면 화면이 다시 그려져요 (useState).
useEffect
"화면이 뜬 뒤 / 값이 바뀐 뒤 이 일을 해" 라고 예약하는 훅. 데이터 불러오기에 써요.
API
앱과 서버가 대화하는 약속. "GET /robot/status로 물으면 로봇 상태를 줄게".
GET / POST
GET은 "가져와", POST는 "이걸 처리해(만들어)" 요청.
상태 코드
서버 답장의 번호. 200 성공, 401 로그인 필요, 409 이미 있음, 422 형식 오류, 503 서버 준비 안 됨.
환경 변수 (.env)
코드 밖에 두는 설정값. 서버 주소·API 키처럼 사람마다 다르거나 비밀인 값.
named export
export function Button처럼 이름을 붙여 내보내기. 이 프로젝트는 export default를 금지해요.
경로 별칭 @/
../../theme 대신 @/theme. @/ = app/src/.
ESLint / Prettier / husky
규칙 검사기 / 자동 줄맞춤 도구 / 커밋 직전에 둘을 자동 실행하는 장치.
네이티브 모듈
